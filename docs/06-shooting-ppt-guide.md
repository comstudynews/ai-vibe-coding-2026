## 6.2 시연 전략
이번 강의는 스튜디오 단독 녹화이므로 학생의 실습 수행 시간이나 질의응답을 넣지 않습니다.
**시연 전 반드시 준비:**
① GitHub에 client·server가 모두 동작하는 기본 저장소를 준비합니다.
② Codespaces 실행 및 Codex 인증을 완료합니다.
③ 프론트엔드·백엔드 초기 버전을 미리 배포합니다.
④ 시연에서는 차량명 검색 결과 건수 표시 또는 입력 검증 개선처럼 **기능 한 가지만 실제 AI로 변경**합니다.
⑤ npm run build, API 호출, git diff 확인 후 Commit·Push합니다.
⑥ 변경 사항이 Vercel·Render에 반영됐는지 확인합니다.
⑦ 클라우드 대기 시 사전 저장한 실행 결과 화면과 로그로 전환합니다.

## 6.4 발표자 설명 핵심 문장
**도입:** "오늘은 AI에게 코드를 작성하게 하는 데서 멈추지 않고, 검증한 코드를 실제 클라우드 서비스로 배포하는 흐름을 보겠습니다."
**PoC·MVP:** "PoC는 기술이 가능한지, 프로토타입은 구현한 화면과 상호작용이 의도에 맞는지, MVP는 최소 제품이 실제 사용자 가치를 제공하는지, 파일럿은 제한된 운영 환경에서 적합한지를 확인합니다."
**세 가지 엔지니어링:** "프롬프트는 작업 지시, 컨텍스트는 필요한 정보, 하네스는 실행 환경과 검증 체계입니다."
**Codex:** "Codex는 저장소를 실제로 읽고 수정할 수 있으므로 먼저 분석을 요청하고, 변경 범위와 최종 결과를 확인하겠습니다."
**배포:** "GitHub Push와 클라우드 자동 배포는 CD의 사례이지만, 자동 빌드·테스트가 갖춰진 완전한 CI를 의미하지는 않습니다."
**마무리:** "오늘 완성한 결과는 데이터가 임시 저장되는 프로토타입입니다. 사용자 계정·영구 저장·보안 등을 보강해야 MVP와 실제 파일럿으로 확장할 수 있습니다."

## 6.7 최종 점검 기준
이 교재를 PPT로 옮길 때 **이론 강의 42분, 실습 시연 37분, 정리 5분, 예비 6분**으로 제한합니다. 교재가 자세하다고 모든 문장과 명령을 낭독하지 않습니다.
**촬영 전 남은 과제:** 플랫폼 계정 준비·Vercel 요금제 검토·Codespaces 실제 실행·Render/Vercel 배포 리허설·학교 공식 템플릿 적용. GitHub 저장소와 자동 검증 워크플로는 생성했습니다. 현재 교재는 코드와 강의 설계 초안이며, 외부 클라우드 배포 완료를 주장하지 않습니다.
